# Roadmap

Where CleanMate is going, and the decisions behind it. Ideas and votes are welcome in
[issues](https://github.com/homielab/cleanmate-linux/issues).

## Done in 1.0

- [x] **Engine + terminal app** — Smart Scan over 50+ locations, cleanup sections, Space Lens,
      Large & Old Files, Duplicates, Uninstaller, Startup Items, Maintenance, System Overview,
      Settings, undo, automatic cleaning, updates.
- [x] **Engine protocol** — `cleanmate.sh --json items|scan|details|clean`, one JSON event per line.
- [x] **Desktop app core** — Smart Scan and the six cleanup sections, details, confirm dialog,
      live progress; system items through the standard password dialog (pkexec + polkit policy).
- [x] **Distribution** — app icon, *Show Apps* launcher, one-line install, `.deb` built by CI on
      every release, AppStream metainfo.

## Next

- [x] **Desktop app: file tools** — Space Lens (drill-down list), Large & Old Files, Duplicates,
      each with an *Undo* toast that uses the engine's Trash code.
- [x] **Desktop app: apps & system** — Uninstaller, Startup Items, Settings (automatic cleaning, updates,
      retention, recent files, activity log), Maintenance, System Overview (the app opens on it).
- [x] **Desktop app: System Overview extras** — the free-space history chart, space outside your folders
      (Timeshift, swap file, reserved space) and your largest folders (a click opens Space Lens there).
- [x] **Launchpad PPA** — `ppa:homielab/cleanmate`, uploaded by CI on every release.
- [ ] **Snap Store** — classic confinement was declined for now (project too new); ask again once
      the project has a track record.
- [ ] **Translations** — the desktop app is in English and Vietnamese (`po/`), cleanup item names and
      descriptions included, following the system's language or the one picked in Settings › Language;
      the engine, the terminal app and scan notes are English only.

The desktop app's *All tools (terminal)* entry is a shortcut to `cm`.

## Design decisions

| Topic | Decision | Why |
|---|---|---|
| Engine | One Bash script (`cleanmate.sh`) | Runs everywhere with nothing to install; the terminal app, the desktop app and the timer share every rule and test |
| Desktop app | Python 3 + PyGObject, GTK 4 + libadwaita 1.5 | Preinstalled on Ubuntu 24.04; native GNOME look, dark mode and accent colours for free |
| GUI ↔ engine | JSON lines over a pipe | The GUI never decides what to delete; the engine can be rewritten later without touching the GUI |
| Privileges | GUI runs as you; system items via `pkexec` | Standard password dialog; as root the engine refuses anything in a home folder |
| Older Ubuntu | 22.04 gets the terminal app only | It ships libadwaita 1.1 (no split view, dialogs, toasts) |
| Packaging | `.deb` first, then a PPA | Flathub doesn't accept host system utilities; Snap needs classic confinement |

## Engine protocol

Every line on stdout is one JSON object with an `"event"` field; sizes are bytes.

| Command | Events |
|---|---|
| `--json items` | `item` (`id`, `category`, `label`, `description`, `default`, `root`, `trash`: cleaning moves it to your Trash instead of deleting it) …, `done` |
| `--json scan [--only LIST]` | `progress` (`done`, `total`, `current`) …, `item` (+ `status` found/clean/timeout, `bytes`, `note`, `selected`, `locked`: the running program that makes a clean skip the item, empty if none, `entries`: `details` lists parts to clean one by one) …, `done` (`ms`, `total_bytes`, `locations`) |
| `--json details ID` | `entry` (`item`, `id`, `bytes`, `label`, `note`: a keyword or empty, `selected`: ticked by default) … for items that can be cleaned part by part, then `details` (`id`, `lines`), `done`. Entries: `docker_dangling` = each dangling image (`id` sha256:…, ticked), `docker_build` = each build-cache record not in use (`id` BuildKit base-32, biggest first, at most 300, a shared record counts 0 bytes, not ticked), `docker_images` = each image no container uses, dangling ones left to `docker_dangling` (`id` sha256:…, `label` = `repo:tag · created …`, bytes = what no other image shares, biggest first, not ticked), `docker_volumes` = each volume no container uses (`id` = its name, `label` = `name · driver`, `note` = `anonymous` (label `com.docker.volume.anonymous` or a 64-hex name) or `data`, biggest first, not ticked); only for a Docker on this computer (unix socket); `trash_drives` = each drive mounted under `/media/$USER`, `/run/media/$USER` or `/mnt` with something in your Trash on it (`id` = the drive's folder, percent-encoded like `Path=`, `label` = its label or folder name and the item count, not ticked; read-only, network and FUSE mounts other than `fuseblk` are skipped); `old_installers` = each installer or disk image at the top of your Downloads folder older than `installer_days` (default 30; a Downloads folder outside your home folder or a symlink is not scanned, the `scan` note says so) (`id` = the file name, percent-encoded, `label` = the name and its age in days, biggest first, not ticked); `old_downloads` = each file or folder at the top of your Downloads folder (no symlinks, no hidden ones) not changed or opened for `download_days` (default 90; a folder counts as touched when anything inside it changed or a file in it was read; folders with more than 20000 files, old installers, unfinished downloads (and the file next to one), open files and Never clean folders are skipped; Downloads outside your home folder: as `old_installers`) (`id` = the name, percent-encoded, `label` = `name · untouched for N days`, a folder's name ending in `/`, biggest first, not ticked); `old_screenshots` = each screenshot or screen recording (`Screenshot from <date>…`, `Screencast from …`, `Screenshot_<date>…`, `Ảnh chụp màn hình …`; .png/.jpg/.jpeg/.webp/.webm/.mp4) at the top of your Pictures folder (`xdg-user-dir PICTURES`, inside your home folder, no symlinks; skipped when it is your Downloads folder) or of its `Screenshots` folder, not changed or opened for `download_days`; open files and Never clean folders are skipped (`id` = the path inside Pictures, percent-encoded, `label` = `name · untouched for N days`, biggest first, not ticked); `abandoned_downloads` = each unfinished download at the top of your Downloads folder (`.crdownload`, `.part`, `.aria2`, `.!qB`, any case; no symlinks) not changed or opened for 7 days; Firefox's empty file of the real name next to a `.part`, and aria2's data file next to a `.aria2`, count in and are moved along (one of them used lately or open: the download is skipped; a non-empty file next to a `.part` is left alone); open files and Never clean folders are skipped, a Downloads folder outside your home folder is not scanned; `old_installers` and `old_downloads` skip these (`id` = the unfinished file's name, percent-encoded, `label` = `name · untouched for N days`, biggest first, not ticked); `vscode_stale_workspaces` = each `User/workspaceStorage` folder of VS Code, VS Code Insiders, VSCodium, Cursor or Windsurf (also Snap and Flatpak builds) whose `workspace.json` points to a local `file://` folder or workspace file that is gone (`id` = the folder's full path, percent-encoded, `label` = `project · editor · N days`, biggest first, not ticked; remote, relative, unreadable or unplugged-drive paths are kept; locked while an editor runs; `globalStorage` is never touched); `stale_build_dirs` = each project whose Cargo `target/`, Python `.venv/`/`venv/` or CocoaPods `Pods/` sits unused for `node_modules_days` (`id` = the project folder's full path, percent-encoded, `label` = `~/path — target/, .venv/ · N days idle`, biggest first, not ticked); `old_runtimes` = each Node.js version of nvm (`$NVM_DIR` or `~/.nvm`, `versions/node/vX.Y.Z`), SDKMAN candidate version (`$SDKMAN_DIR` or `~/.sdkman`, `candidates/<name>/<version>`, no symlinks) Flutter version of fvm (`~/fvm/versions`, `$FVM_CACHE_PATH/versions`), Python version of pyenv (`$PYENV_ROOT` or `~/.pyenv`, `versions/<name>`), Ruby version of rbenv (`$RBENV_ROOT` or `~/.rbenv`, `versions/<name>`), rustup toolchain (`$RUSTUP_HOME` or `~/.rustup`, `toolchains/<name>`) and Go SDK (`~/sdk/go<version>`, from `golang.org/dl`) that isn't kept: nvm keeps `alias/default` (through `alias/lts/…`; `node`/`stable` = the newest), what its other aliases name and the `node` on PATH; SDKMAN keeps each candidate's `current`; fvm keeps the version its `default` link names; pyenv keeps what every line of its `version` file names (`3.12` = every 3.12.x, a `python-` prefix dropped, a virtualenv link = the version it lives in; `system` keeps none) and versions holding virtualenvs (`envs/`); rbenv keeps the first word of its `version` file (`ruby-` dropped); rustup keeps `default_toolchain` and every `[overrides]` value of `settings.toml` (a name without a host triple matches any host); Go keeps the SDK each `go` command (PATH, your profile's PATH, `/usr/local/go/bin`, `~/go/bin`, `~/bin`, `~/.local/bin`, `/usr/lib/go/bin`, `/usr/bin`, `/snap/bin`) runs from or reports as `go env GOROOT` and any SDK your profile or `~/.config/go/env` names; pyenv, rbenv and rustup also keep a version your PATH runs from; no default that can be told (no readable file, a name nothing installed matches, `rustup default none`, a `go` that fails, a profile picking the SDK by variable, no `go` and no SDK named) → that tool keeps everything; links in `versions/`/`toolchains/`, shims, `version`, `settings.toml` and `~/.rustup/downloads` are never touched; versions a process runs from or has a file open in are left out and named in the scan `note` (`skipped while running: …`) (`id` = the folder's full path, percent-encoded, `label` = `Node vX.Y.Z` / `<candidate> <version>` / `Flutter <version>` / `Python <name>` / `Ruby <name>` / `Rust <toolchain>` / `Go <version>`, biggest first, not ticked); `android_images` = each Android emulator system image (`system-images/<android-N>/<tag>/<abi>` with a `source.properties` or `package.xml`, in `~/Android/Sdk`, `ANDROID_HOME` or `ANDROID_SDK_ROOT` inside your home, no symlinks) whose folder no AVD's `config.ini` names in `image.sysdir.N` (`id` = the image folder's full path, percent-encoded, `label` = `Android N · tag · abi`, biggest first, not ticked; AVDs are read from `~/.android/avd`, `ANDROID_AVD_HOME`, `ANDROID_USER_HOME/avd` and `ANDROID_SDK_HOME/.android/avd`, `<name>.ini` `path=` included — one that can't be read lists nothing; locked while Android Studio, the emulator, sdkmanager or avdmanager runs; deleted for good); `jetbrains_old_versions` = each JetBrains IDE or Android Studio version (`<Product><year>.<n>`: `IntelliJIdea2023.1`, `AndroidStudio2023.3`; in `Google/` only `AndroidStudio…`) under `JetBrains/` or `Google/` of `~/.config`, `~/.local/share` and `~/.cache` (`XDG_*_HOME` respected), also inside each Flatpak (`~/.var/app/<id>/{config,data,cache}`) and Snap (`~/snap/<name>/<revision>/{.config,.local/share}`, `~/snap/<name>/common/.cache`) sandbox, that a newer version of the same product in the same place replaced (versions compared numerically, the three folders together); never the newest version nor a name without a version (`consentOptions`, `IntelliJServer`, `Daemon`, `Toolbox`); its folders in the three places are one entry (`id` = its first folder's full path, percent-encoded, `label` = `IntelliJ IDEA 2023.1`, plus ` · Flatpak` / ` · Snap` from a sandbox, biggest first, not ticked); versions of an IDE that runs (its launcher `idea`, `pycharm`, `studio`… or `<name>.sh`, or java with `idea.paths.selector=<Product>`) or that a program has a file open in are left out and named in the scan `note` (`skipped while running: …`); moved to the Trash); `ai_model_caches` = each model PyTorch Hub, Whisper, sentence-transformers or Keras downloaded: a file in `<torch>/hub/checkpoints`, a `*.pt` in `<cache>/whisper`, a folder with `modules.json` or `config_sentence_transformers.json` in `<torch>/sentence_transformers` or `SENTENCE_TRANSFORMERS_HOME`, and `models/` and `datasets/` of `~/.keras` and of `KERAS_HOME` when it holds `keras.json` (`<cache>` = `~/.cache` and `XDG_CACHE_HOME`, `<torch>` = `<cache>/torch` and `TORCH_HOME`; variables only inside your home folder; no symlinks; a folder two libraries would claim, and a model folder holding another library's folder, are left out; open files and Never clean folders are skipped) (`id` = the model's full path, percent-encoded, `label` = `<name> — PyTorch Hub` / `<name without .pt> — Whisper` / `<folder> — sentence-transformers` / `models|datasets — Keras`, biggest first, not ticked; deleted for good; `torch/kernels`, Hub repos, `keras.json` and the Hugging Face cache are never touched) |
| `--json [--dry-run] clean ID…` | `task` (`id`, `state` run/ok/skip/fail — skip while the item's program runs, `info`, `freed`) …, `done` (`freed`, `avail_before`, `avail_after`, `trash`: item ID → keys of what it moved to the Trash, for `restore`; `{}` on a dry run or when nothing went to the Trash) |
| `--json [--dry-run] clean ID --entries E1,E2…` | Same events; cleans only these entries of one item (`docker rmi ID` / `docker builder prune --force --filter id=ID` / `docker rmi` with every tag of the image (its ID when untagged) / `docker volume rm NAME` / empties that drive's `files/` and `info/`, keeping the folders and anything a program has open / moves those files to your Trash / deletes those Android image folders / moves the folders of those IDE versions to your Trash). Each ID must match the item's format (else `error`, exit 2, nothing is called) and be one `details` lists now (others are skipped; none left → `fail`). Dry run: `freed` = the entries' size |
| `--json large [--min BYTES] [--days N] [--path DIR]` | `file` (`path`, `bytes`, `mtime`, `atime`, `kind` video/audio/image/archive/package/disk/document/other) … biggest first, at most 500, `done` (`count` listed, `found` matched, `total_bytes` listed). Defaults: 100 MB, any age, your home folder; `--days` = neither changed nor opened for N days; skips `.cache`, `.git` and Trash folders, Never clean folders and other file systems |
| `--json lens [--path DIR]` | `entry` (`path`, `bytes`, `kind` dir/file — a link is a file, `count` files and folders inside a folder or 1, `movable`: inside your home folder and not protected, or below the top folder of a drive mounted for you (`/media/$USER`, `/run/media/$USER`, `/mnt`) that is writable and not a network or FUSE file system (`fuseblk` is fine; the same rule as `trash_drives`), on that drive's file system, not in its Trash or a `timeshift`/`timeshift-btrfs` backup folder at its top, and not reached through a symlink leading off the drive — never a Never clean folder or one holding one; `excluded`: it is, is in or holds a Never clean folder) … biggest first, at most 500, `done` (`path`, `bytes` and `items` of DIR, `count` listed, `found` entries, `excluded`: DIR is in a Never clean folder, `drive`: the top folder of the drive DIR is on (or is), else empty, `drive_trash`: that drive is writable and local, so its things can go to its Trash). Measured like `du -x -b` (one file system), as you; default your home folder; skips names that aren't UTF-8 |
| `--json dupes [--min BYTES] [--path DIR]` | `progress` (`stage` list/compare/verify, `done`, `total`) …, `group` (`hash` MD5, `bytes` of one copy, `files` [{`path`, `mtime`}] newest first) … biggest files first, at most 500, `done` (`groups` listed, `found` groups, `files` listed, `total_bytes` freed by keeping one copy of each listed group). Same size → same MD5 of the first 64 KB → same full MD5, like the terminal app; defaults: 1 MB, your home folder; hard links count once; skips empty files, hidden folders, `node_modules`, Never clean folders, other file systems and names that aren't UTF-8 |
| `--json [--dry-run] trash [--home-only] PATH…` | `task` (`id` = the path, `state` ok/fail, `info`, `freed`, `trash`: its name in your Trash, or for a file on a drive mounted under `/media/$USER`, `/run/media/$USER` or `/mnt` its path in that drive's own Trash (`<drive>/.Trash/<uid>/files/…` for an admin's sticky `.Trash`, else `<drive>/.Trash-<uid>/files/…`, made if missing; `Path=` relative to the drive); empty when it can't be put back — other places outside your home folder, a read-only drive or a dry run, which go through `gio trash`) …, `done` (`moved`, `failed`, `freed`). `--home-only` (Space Lens: your home folder or a writable drive) fails what `lens` marks not `movable`; anything in, or holding, a Never clean folder fails in any case. Refused as root |
| `--json [--dry-run] restore KEY…` | `task` (`id` = the original path, `state` ok/fail, `info`, `trash`) …, `done` (`restored`, `failed`). KEY is a `trash` value; a file is put back only inside your home folder, or on the drive whose Trash it is in (that Trash must be yours, not reached through a symlink), never over an existing file. Refused as root |
| `--json startup` | `unit` (`id` autostart:FILE.desktop or systemd:UNIT, `kind` autostart/systemd-user, `name`, `enabled`, `path`, `system`: comes with the system, `hidden`: a NoDisplay entry or the system's own service, `toggle`: can be switched here, `removable`, `description`, `command`) …, `done` (`count`, `systemd`: false when `systemctl --user` doesn't answer). Your `~/.config/autostart` and the system's entries (`/etc/xdg/autostart`); systemd user services and timers that are enabled or disabled — the system's own only when enabled, view only. Refused as root |
| `--json [--dry-run] startup-set ID enable\|disable\|remove` | `task` (`id`, `state` ok/fail, `info`, `trash`: name in your Trash after `remove`), `done`. Autostart: off = `Hidden=true` (a system entry gets your own copy, the system file is never changed), on = removes `Hidden=` and `X-GNOME-Autostart-enabled=false`; `remove` only your own entries (not a copy of a system one), to the Trash. systemd: `systemctl --user enable\|disable` for units in your `~/.config/systemd/user` or `~/.local/share/systemd/user`; `remove` (disable, Trash, daemon-reload) only in `~/.config/systemd/user`. Undo = `restore`. Refused as root |
| `--json settings` | `setting` (`key`, `value`; numbers also `min`, `max`, `default`) for `language` (`value` system/en/vi, `choices`, `default`: the desktop app's language, which reads the file itself at start-up; the terminal app stays English), `schedule` (`value` off/daily/weekly/monthly, `choices`, `default`: automatic cleaning, read from the systemd user timer), `update_check` (0/1), `low_disk_pct`, `journal_days`, `journal_mb`, `log_max_mb`, `app_log_days`, `tmp_days`, `cache_days`, `node_modules_days`, `installer_days` (`old_installers`), `download_days` (`old_downloads`, `old_screenshots`), `ai_history_days`, then `selections` (`value` = number of remembered Smart Scan choices), `recent_files` (0/1: GNOME's `org.gnome.desktop.privacy remember-recent-files`; only when `gsettings` can read it), `exclusions` (`value` = list of the Never clean folders, from `~/.config/cleanmate/exclude`, one path per line; lines that can't be excluded are ignored), `done` (`systemd`: `systemctl` exists, `packaged`: updates come from apt/snap). The terminal app's settings file `~/.config/cleanmate/settings`; a missing or out-of-range value reads as its default. Refused as root |
| `--json [--dry-run] settings-set KEY VALUE` | `task` (`id` = KEY, `state` ok/fail, `info`), `setting` (KEY as saved now), `done`. `language system\|en\|vi` saves the desktop app's language (shown after a restart); `schedule off\|daily\|weekly\|monthly` writes and enables (or disables and removes) `cleanmate.timer` at once; `selections reset` forgets remembered choices; `recent_files 0\|1` sets GNOME's remember-recent-files (`error` without `gsettings`); `exclusions add\|remove PATH` adds a Never clean folder (`state` fail with the reason when it isn't an existing folder inside your home folder, is your home folder or above it, or is reached through a symbolic link) or removes one; a number must be within its range. Only that line of the settings file changes. A wrong key or value: `error`, exit 2. Refused as root |
| `--json activity [--limit N]` | `activity` (`epoch`, `text` = the log line without its time) for each line of the activity log `~/.local/state/cleanmate/clean.log` (what the terminal app shows in Settings › Activity log), newest first, at most N (default 1000); `done` (`count`, `path` = the log file). No log yet: `done` with `count` 0 |
| `--json apps` | `app` (`id` = KIND:PACKAGE, `kind` apt/snap/flatpak, `name`, `bytes` of the app, `data_bytes` of its folders, `last_used` epoch or 0, `desktop` launcher id, `leftovers` [{`path`, `bytes`}]: folders in your home only this app uses) …, then `leftover` (`path`, `name`, `kind` flatpak/snap/folder, `bytes`): folders of apps already removed (`orphan_folders`; offered unticked, through `trash --home-only`) …, `done` (`hidden`: parts of Ubuntu left out) |
| `--json uninstall --check ID…` | `check` (`ok`, `message` why not, `extra` number and `extra_text` of other packages apt would remove, `running` = `[{id, program}]` of apps that are running and will be skipped), `done` |
| `--json [--dry-run] uninstall ID…` | `task` (`id`, `state` run/ok/fail/skip, `info`) …, `done` (`removed`, `failed`, `skipped`). Only IDs `apps` lists; apt removals that would take a part of Ubuntu are refused. A running app is skipped. apt and Snap need root (`pkexec`): one `apt-get purge` and one `snap remove` for all the apps given, each app still reported on its own. Flatpak runs as you, one app at a time. Leftover folders: `trash` as you, after the app is gone |
| `--json maintenance` | `maint` (`id` update/repair/flatpak_unused/fstrim/free_ram/fonts/locate/snap_versions/journal_limit, `label`, `description`, `available`: its tool is installed, `reason` why not, `root`: has steps that need root, `user`: has steps run as you, `toggle`: a lasting limit switched on or off, `on`, `value` now — snap's `refresh.retain` or the journal limit in MB, empty if none — and `target`: what `on` sets) … the terminal app's nine Maintenance items in its order, `done` |
| `--json [--dry-run] maintain ID [on\|off] [--user-steps]` | per step `task` (`id` step, `label`, `state` run/ok/skip/fail, `info`) with its output as `log` (`line`) in between, `done` (`ok`, `failed`, `skipped`). `on`/`off` only and always for `snap_versions` and `journal_limit`. As root only the steps that need root run (a user-only item: `error`); as you every step runs (root steps via `sudo -n`) — `--user-steps` runs only yours, after the root part through `pkexec`. Unknown item, missing tool: `error`, exit 2 |
| `--json overview` | `system` (`os`, `kernel`, `cpu`, `threads`, `uptime` seconds, `apt`/`snap`/`flatpak` package counts, `null` when the tool isn't installed), `disk` (`mount`, `fstype`, `device`, `size`, `used`, `avail`) … for each real filesystem (no tmpfs, squashfs, overlay), `memory` (`ram_total`, `ram_used`, `ram_avail`, `swap_total`, `swap_used`), `freed` (`days` 30, `bytes` and `cleanups` in those days, `since` first recorded cleanup, `lifetime`, `runs`, `last_time`, `last_bytes`) only once a cleanup was recorded, `protection` … one per check (`id` `firewall` / `apparmor` / `updates` / `secureboot`, `state` `on` / `off` / `unknown` / `na`, `reason` — firewall `ufw` / `firewalld` / `disabled` / `inactive` / `missing` / `unreadable`, apparmor `loaded` / `service` / `kernel` / `unreadable`, updates `on` / `missing` / `disabled` / `timer` / `no-apt` / `unreadable` (state `unknown`: apt-config fails or is missing, or APT's settings can't be read; never `off`), secureboot `on` / `firmware` / `legacy` / `unreadable` —, `command` that turns it on for the user to run, `""` when none; read without root, nothing changed), `history` (`points`: the last 30 recorded days, oldest first, each `time` = epoch of the day, `avail` and `size` of `/`; recorded once a day when a scan, a cleanup or this command runs, in `~/.local/state/cleanmate/disk-history.tsv`), then the slow part (du): `outside` … (`kind` `reserved` / `swapfile` / `timeshift`, `bytes` or `null` when it can't be measured without root, `path`, `count` of Timeshift snapshots, else 1, `note` in English) for space in use outside your folders, `top_dirs` (`home`, `dirs`: up to 12 folders right in home, `path`, `bytes`, biggest first), `done`. Everything up to `history` comes within about 100 ms. Cleanups are recorded in `~/.local/state/cleanmate/cleanups.tsv` (epoch, bytes; last 1000) |
| any error | `error` (`message`), non-zero exit |
